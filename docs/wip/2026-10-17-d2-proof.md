## Terminal move and capture restart

Decision 79 uses the proved std hard-link/unlink sequence, without a new dependency or unsafe code. A permanent primitive journey first ran on the worktree's APFS volume: an occupied destination returned AlreadyExists with both files byte-identical, and a process kill between link and unlink retained two names with equal device/inode and unchanged contents (`native_move_link`, one passed, exit 0).

`cargo test -p fleet-sync-writer --offline --lib writer_move_tests` passes three tests (exit 0): the file includes committed WAL data after moving, only durable registration rejection permits a move, guarded readers and occupied destinations refuse before closing the source, path aliases cannot unlink the destination itself, repeats succeed, and a retry never creates a missing source. The first replay exposed a 32-byte WAL header from Turso's verification open; verification now checkpoints and closes on every retry, preserving the strict empty-WAL gate.

`cargo test --manifest-path tests/consumer/Cargo.toml --offline --test native_move_aside -- --nocapture` passes its real process journey (one passed, exit 0). Three registrations are refused over WebSocket; their accepted writes remain as rejected tails. After joining the writer runtime, the mover is killed before link, between link and unlink, or after unlink. Each associated retry succeeds twice, keeps exact integer/blob cells and the original rejected-tail positions, and leaves no source. Source WAL and SHM are absent or empty at every kill boundary. Occupied destinations are refused with both files byte-identical. Strict Clippy for writer/runner/service and the standalone consumer passed after this implementation.

`cargo test --manifest-path tests/consumer/Cargo.toml --offline --test native_capture_restart -- --nocapture` passes one journey (exit 0): the receiver commits a first split part, the socket closes before that answer reaches the sender, and the receiver process is killed while replicated rows remain unpublished. The writer file reopens, the same session reconnects, and the final part commits before another socket close hides its answer. A second receiver restart replays the final receipt as AlreadyApplied. Resending completes the sender's durable acknowledgement without repeating rows or hook effects; subsequent updates and deletes preserve exact cells, composite keys and NULLs.

## Registry workflow integration

After restacking onto the registry workflow implementation, `cargo test -p fleet-sync-lease -p fleet-sync-writer -p fleet-sync-tokio-runner --offline` passes 150 tests, zero failed, exit 0. The duplicate runtime dependency introduced by the restack was removed in its own repair commit.

The service now admits every holder change through the registry's canonical admission transaction. Admins supply their authenticated ActorRef; a peer Claim uses its verified session peer. Both holder-change tasks use the registry object's shared clock. The service returns the canonical domain answer and signals its joined registry runner after the admission commits. Cancellation does the same post-commit timer signal. The view passes the registry's typed result through unchanged. No peer cancellation API was added.

`cargo test --manifest-path tests/consumer/Cargo.toml --offline --test native_writer_cancel -- --nocapture` passes three real journeys (exit 0):

- Cancellation commits while the holder's Release answer is unanswered. The holder resumes at its original epoch and a late Release under the original CallId is refused over the live session. Its per-copy acknowledgement and capture stream survive pruning and writer reopen; the authoritative copy contains all 304 expected exact rows afterwards.
- Cancellation after the holder answered Released, while the copy is still behind, prevents fencing. The accepted row finishes draining, then the holder writes and receives acknowledgement again at the same epoch.
- A takeover supersedes a Cancelling move whose withdrawal answer remains unanswered. The copy retains all 301 rows, the next epoch skips the cancelled reservation, and the old writer refuses admission once its own authority watch observes supersession.

The first nonblocking admission integration failed all three cases because a persisted journal wake did not itself signal the Tokio timer. Adding the post-commit Host wake, using the existing snapshot-install pattern, corrected this without manual polling or a detached runner. A fixture also initially dropped an admin socket without a close frame; closing it through its transport corrected that test-side reset. The takeover test waits for the specific Superseded authority predicate rather than treating an earlier periodic-renewal event as completion.

The original-deadline boundary has real-Turso tests that reopen from the durable request start and refuse exactly at the original deadline. A native clock journey below also waits for that actual deadline, observes expiry and renews the same epoch.

## Two-copy retention recovery

`cargo test --manifest-path tests/consumer/Cargo.toml --offline --test native_retention -- --nocapture` passes one real journey (exit 0). An actual disconnected follower remains at capture position 9 while the authoritative copy advances to 27. The configured window is 14 capture IDs, and the test asserts that the lag is beyond it. The sender reports CopyNeedsSnapshot. After killing and restarting the follower service, an attached source session installs a new snapshot into that same follower. Its original start cursor stays 9; its acknowledgement advances to 27, and its snapshot flag clears. A previously copied, then deleted row stays absent.

The writer reopens and runs the later migration. Both copies acknowledge position 40, then the next write at 42, with the same nine final rows, eight migrated values and one new NULL value. The migration spans 13 capture IDs; the test explicitly checks it fits the configured window while the earlier 18-ID lag does not. The initial smaller fixture window legitimately marked the follower for another snapshot during that bulk migration; the observed spans now determine the fixture policy without weakening the needs-snapshot assertion.

The fixture's first attempt also used its writer's peer credential for a separate snapshot-reader session, which correctly ended the writer's old session. SessionRules and the actual SessionEnded frame established that cause. The fixture now supplies the source reader's peer explicitly and uses a distinct peer in this journey; the service's session rule was not changed.

## Lifecycle and publication recovery

`cargo test --manifest-path tests/consumer/Cargo.toml --offline --test native_lifecycle -- --nocapture` passes two journeys (exit 0). A captured backup is imported and seeded through actual pages. Re-import repeats are stable and conflicting content refuses. A peer claims it at epoch 2; the consumer commits settlement but withholds its answer. The admin view already reports Granted with settlement owed. Killing and restarting the registry retries that same CallId, clears the debt and retains Granted. A resumed session's fresh Welcome reports the epoch and exact copy position. Renewal A replays its original recorded answer after renewal B and after a takeover, while reporting the current epoch separately and leaving the new holder's deadline unchanged. Another registry restart grants a still-higher epoch. Revocation closes a bound connection and refuses new authentication while the lease remains valid. The second journey retires an unheld imported database, checks replay and the typed Retired answers for import, claim, renewal, registration, copy status and seed begin.

`cargo test --manifest-path tests/consumer/Cargo.toml --offline --test native_lease_transitions -- --nocapture` passes three journeys (exit 0):

- An actual Release/Withdraw exchange restores same-epoch writing. At the recorded original request deadline, admission pauses and a fresh Welcome reports Expired. A renewal resumes the same epoch, and the accepted rows reach the copy.
- A takeover fences the copy while the old writer still has an unexpired local lease. The copy refuses its accepted tail with StaleEpoch; the writer persists and reports that tail, remains readable and closes its write gate. The copy retains only the authoritative rows.
- A move just beyond the configured renewal bound returns HolderStale with the recorded last-renewed time. After a real renewal, a move starts inside the bound, drains an accepted write and grants the next epoch at that position. These waits use the actual clock event, not repeated polling or a substituted clock.

The consumer's HolderChangeGate now persists reservations and terminal settlements in its own Turso file through generated checked queries. `cargo test --manifest-path tests/consumer/Cargo.toml --offline --test claim_gate` passes one test (exit 0): settling Cancelled before reserve closes the attempt, including after reopen; a late reserve refuses, a conflicting outcome fails, and a repeated settlement retains its original CallId.

The bootstrap suite now passes two process-kill journeys (exit 0), covering conversion before rename and publication after rename plus parent-directory fsync but before reopen. Both resume generation 1, migrate the copied rows, replicate the next write and remove receiver-only bookkeeping from the writer file. The fault seam is available only with `test-support`.

The capture restart suite now passes two journeys (exit 0). Its additional journey kills the receiver after the copy transaction has admitted its hook follow-up, before that follow-up produces an external effect. On reopening, the already-applied piece stays unchanged and the original CallId runs once. This complements the lost-answer-after-effect case in `native_service`.
