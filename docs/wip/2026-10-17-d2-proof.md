The bootstrap journey starts a real service and two separate writer processes over localhost WebSocket, backed by Turso files. After the old holder registers 301 rows, the move grants epoch 2 at its final position. The new holder refuses writes while Seeding. The test kills that process after staging conversion and before publication, then restarts it under its persisted session. The same install ID and generation 1 reach Ready. A later consumer migration changes all 301 copied rows; a new epoch-2 write then reaches the authoritative copy, which contains 302 rows. The old writer refuses admission. Inspection after the new writer closes confirms all four receiver bookkeeping tables are empty in its published file.

Withdrawal retains the cached lease through Released, including renewals that leave its gate closed. Its own CallId receipt acts as a permanent transfer tombstone. Reopening applies durable authority with its original request start time, suppresses that transfer's release records, and leaves another drain, Superseded or Retired intact. The native session handler commits the receipt before answering. Real cancelled-move session proof is still pending the registry workflow half.

The first holder and writer withdrawal builds failed because the withdrawal methods did not exist. Strict Clippy later caught an install-runtime type-complexity error; a private engine alias corrected it without relaxing the lint.

Move-aside (decision 79), additional process/reconnect coverage, retention recovery, remaining lifecycle journeys, final standalone/WASM gates, hosted CI and independent verification remain open. No deployment, merge or complete D2 acceptance is claimed.
