# C27: preserve receiver-rule storage errors

This slice follows C23 and implements governing program design §13a W-C29 and r4 plan row C27, including the bridges, native-driver certainty and caller-control amendments, reread at governing design commit 53d47814e11290ec50ec3a5a6a2a5fe6fefe5217. It changes both `ReceiverRules` callbacks to return `HookError::{Refused(HookRefusal), Storage(fleet_sync_receiver::StoreError)}`. Consumer SQL errors use one public named conversion over the receiver's existing classifier. Business refusal remains terminal; storage follows the receiver's existing storage and rollback paths. Apply, seed publication and snapshot install-ready are in scope. No new store seam or rollback marker is authorized.

The later W-C29 driver amendment also authorizes private native transaction bookkeeping below unchanged TursoStore and AtomicStore. A real single-row full can make Turso end the whole transaction, while the receiver's upsert uses a statement savepoint and keeps the outer transaction live. The driver records automatic rollback only when the same tracked transaction was live immediately before an ordinary failed statement and actual engine autocommit confirms it ended afterward. Caller transaction control, uncertain engine-state reads and commit-capable statements cannot establish that proof. The observation wraps row-stream errors too. Recorded rolled-back transactions reject further statements and nested begins; explicit and dropped nested handles unwind without reviving them. A fresh top-level begin resets the private state. Existing failed boundary precedence remains.

All local implementation gates passed on the declared diff: 656 workspace parent tests and 95 external consumer tests, with zero failures. The workspace has two existing ignored entries, explained below; none of C27's new cases is ignored. Final scoped Clippy, format checks, wasm library/worker compilation, durable metadata, and all nine query-generator checks passed. CI and independent observation are separate immutable-target claims, still pending at this checkpoint.

## Source checkpoint

At the C23 base, `apply_rules` maps every callback error to `PieceRefusal::Hook`; `seed_rules` maps every snapshot callback error to `SeedAnswer::Hook`. The shared snapshot helper also feeds `SnapshotInstallRules::mark_ready`, whose existing `SnapshotInstallError::{Hook, Storage}` can preserve the distinction without adding an error channel. Existing `apply_rollback`, `receiver_rollback` and `classify_copy_store_error` already give storage-full a retryable answer and give failed storage boundaries precedence.

The pinned Turso 0.8.1 implementation supports `PRAGMA max_page_count`: its pager clamps a lowered limit to the current database size and returns `DatabaseFull` when allocation would exceed it. The permanent scenarios observed this real error reaching the public receiver conversion as `Full`. Only fixture database page caps changed; the host disk was not exhausted by these scenarios.

## Required proof

Permanent real-Turso cases must make the rule's own SQL fail full after receiver rows change, using the public conversion. They cover the final multipart part with earlier staged parts retained, seed publication, and install-ready. After lifting the cap, the identical request must finish once. Inspect canonical rows, consumer summary, acknowledgement and receipts, seed pages and publication/install markers, and follow-up admission. Keep business refusal terminal and failed rollback unknown. The wrong build that maps storage to refusal must fail these cases.

The closest test-design example is the field that the schema did not know: a callback's error type alone cannot prove the composed outcome. The real SQL error, consumer conversion, receiver callback, transaction rollback and final classifier must remain in the test path. Expected unavailable/refusal variants and durable-state literals come from W-C29, rather than from the production classifier.
