## Behavior exercised

Receiver proof uses actual Turso scopes for whole and split pieces, exact continuation, per-piece receipts and replay, conflicting content, gaps, historical-holder cutoffs, fencing, moved snapshot pagination, protected schema, hook-local membership, local migrations, seed generation/digests and retirement erasure. SQL binding/readback retains signed 64-bit integers, real storage classes and signed infinities. Split-piece and seed-page persisted JSON retain a sensitive finite value bit-for-bit after file reopen.

The real engine and file-backed Turso journal exercise admission in the producer transaction, rollback, stable call identity after a lost answer, and no extra admission on receipt replay. Seed publication calls the snapshot hook after installed rows are visible; a refusal rolls back rows, ready state, hook writes and new follow-ups together. Snapshot follow-ups have distinct identities from retained piece follow-ups at the same replication position.

Registry proof uses real registry transactions, actual copy rules, consumer gate receipts and the engine. It covers copy-first registration/import, immutable creation identity, renewal replay with fresh authority, Move/Takeover/Claim ordering, persisted supersession before resuming a pending call, both old-fence/takeover interleavings, one copy-proven floor repair, refusal of a second repair, unavailable calls, pregrant and postgrant failure cleanup, every reachable typed terminal copy refusal after a reserved Claim, successful Takeover request-key replay, and retirement replay. A checked registry inventory validates row identity and excludes permanently retired and unknown databases without file discovery or peer calls. Missing, inconsistent and exhausted epoch floors cannot manufacture authority.

Behavioral regressions were observed before the corresponding fixes for local-schema leakage, premature continuation of a superseded move, copy-proven floor recovery, native infinity decoding, the snapshot callback/admission path, typed permanent follow-up outcomes and registry inventory. The latter two were tested against compilable API scaffolds before behavior wiring. Other moved or added cases were first run after their implementation; no pre-fix behavioral red is claimed for those. Compile errors and fixture mistakes were corrected separately and are not counted as behavioral regressions.

## Runtime evidence and limits

The actual workerd foundation journey was extended from nine to eleven exact numeric values/classes, including positive and negative infinity stored and read as REAL. It passed the suite endpoint, effect-after-commit, induced storage failure and committed-row recovery after runtime restart. It used the matching wasm-bindgen tool rather than the older global binary. A fresh rebuild, matching-tool bundle and runtime run also passed on the final dependency head before the follow-up/inventory and coverage delta; the workerd code is unchanged by that delta. The separate inherited Wrangler worker source was extended and compiled, but its optional journey was not run.

Same-process journal/file reopen is not a process-kill test. Holder release/drain is a receipted stand-in for D2's writer. Snapshot file rename, fence/receipt carry into a replacement file, actual writer release, WebSocket delivery and SV1–SV3 belong to D2 and are not established here. The controlled capacity case injects SQLITE_FULL at the SQLx executor after an actual first-row write and proves Turso rollback; it does not exhaust the physical disk.

Copy foreign-key enforcement is deliberately disabled on both runtimes. Writers own integrity and copies apply whole writer transactions; this does not claim copy-side FK validation. Consumer hook code owns follow-up deduplication by CallId. Hosts must initialize local hook migrations, check registry lifecycle before returning cached operation answers, and roll back typed postwrite refusals before replying.

Permanent consumer follow-up failures are saved as typed call answers and reported as operation refusals with the same code. Retry is unsaved AnswerLost and uses the same CallId and the engine backoff. A deterministic interruption after the real journal saves Failed, followed by reopen with the production task, proves that the hook is not called again. KEEP_RESULT=false releases finalized operation records, so the refusal code is observed in DriveReport.failed; the producer receipt still prevents extra admission.
