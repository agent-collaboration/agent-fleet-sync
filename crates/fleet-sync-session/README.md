# fleet-sync-session

Session rules persist logical sessions and notices through the caller's borrowed SQLx transaction. They return effects for the host to execute after commit. Dropped, replaced, malformed, and expired connections detach a session; a new session ID or peer revocation ends it. A closed old connection cannot reattach or detach its replacement.

The host implements `SessionScope: durable_steps::storage::TransactionScope`. SQL belongs to this crate; the extra scope methods read and stage host-owned `ConnectionRegistration` values. On Tokio these live beside socket tasks; on a Durable Object they belong in socket attachments. Clone or otherwise stage registration edits with the transaction, publish them only after commit, and discard both edits and effects on rollback. Pass event time to every rule; rules read no clock and spawn no tasks.

Apply `SESSION_MIGRATOR` alongside application migrations in the same host-owned migration transaction. The session corpus is generated by `fleet-sync-query-gen`; its build script verifies committed metadata without a regeneration bypass. Notice positions use decimal TEXT so the full `u64` range survives both drivers. Private row decoding checks required fields, keys, JSON, and notice positions before returning domain values.

`SessionEffect::Welcome` asks the host to gather the peer's current registry and copy status after commit. Send a fresh Welcome for every attachment and repeated Hello. Report each unreadable copy as `DatabaseStatus::Unavailable`; close the connection if the overall gather fails, so the next Hello reads again. The session crate does not read registry or copy tables.

`SessionClient` owns frame correlation and persisted session ID/notice cursor through `SessionClientStore`. Connection loss reports pending frames as `Unknown`. The consumer decides whether to resend its typed operation identity; the transport cannot decide whether that operation committed. Explicit notice acknowledgment advances the cursor after handling. The host supplies reconnect time, wake scheduling, IDs, transport pumping, credentials, and persistence; an ended session requires `start_new_session`.

Run the rule and client tests with `cargo test --locked -p fleet-sync-session`. The WebSocket crate's permanent two-process journey exercises these rules over actual localhost sockets and native Turso transactions. Its registry, lease, and consumer receipt behavior are fixture stand-ins; it does not prove the receiver, registry, delivery milestone, or Cloudflare deployment.
